# Agent 任务领取与交接协议

这是所有参与 Living Reader 开发、研究、验收或协作的 Agent 共用的任务入口。**Teable 是任务控制面；聊天、handoff 和本地计划只能指向它，不能代替它。**

## 一个公共队列，一套生命周期

长期 Agent 不按名字拥有专属队列或专属流程。所有长期 Agent 都从`可领取任务`进入，领取后在`负责人`记录当前身份，然后沿同一状态流向前。

```text
待细化 → 已就绪 + 可领取 → 开发中 → 待验收 → 回归中 → 完成
                              └→ 阻塞 → 条件解除后返回可执行状态
```

- `负责人`只回答“现在谁负责下一步”，不改变工作流。
- `可领取`只回答“任务合同是否完整到可以开工”，不绑定某个 Agent。
- `完成`是独立验收结果，不是实现者的自评。
- 新增 Agent 时只增加可识别的`负责人`选项；不新建`<Agent>就绪`字段、`<Agent>可领取`视图或另一套状态机。

## 每次会话的固定入口

1. 确认工作区、worktree 和 Git 现状，读最近的 `AGENTS.md`。
2. 读 Teable 当前队列。已有指定任务时，仍要重读该记录，不从聊天或 handoff 恢复旧状态。
3. 读任务的`范围内`、`不在范围`、`技术方案`、`开发指令`、`目标路径`、`验收标准`、`验收命令`、`风险与回滚`和`依赖任务`。
4. 读链接的`验收与回归`、`关联功能`和`关联 ADR`；返工任务还要先读`验收证据`中的退回原因。
5. 信息完整后才能领取或继续。缺少会改变实现方向的信息时，任务保持/返回`待细化`，Agent 不自行发明要求。

**没有完成本轮 Teable 读取，就不开始实现、研究或验收。**

## 领取与防冲突

1. 从`可领取任务`按视图顺序选择第一条依赖已完成且自己有能力执行的任务。
2. 领取时在同一次写回中把`负责人`改为自己，把`状态`改为`开发中`。
3. 立即重读记录。只有`负责人=自己` 且 `状态=开发中`时才算领取成功；若被其他 Agent 抢先写入，停止并重新查队列。
4. 同一个长期 Agent 默认只保持一条在途开发任务；任务合同明确允许的并行泳道除外。
5. 当前`负责人`没有自己的可选值时，停止领取并请求增加身份；不借用其他 Agent 名称。

如果只是用户或父 Agent 交付的单次回答、不进入项目实施/验收链，无需创造虚假领取。一旦会修改项目或产生验收结论，就必须有 Teable 任务。

## 独立验收与交接

- 实现完成：先写`验收证据`，再把`状态`改为`待验收`，使其进入公共`验收队列`。
- 验收领取：任一长期 Agent 可从`验收队列`领取，把`负责人`改为自己、`状态`改为`回归中`，然后重读确认。尽可能不由原实现会话验收自己的结果。
- 验收通过：写完证据后改为`完成`。
- 验收失败：写明精确缺口、复现命令和失败路径，改回`已就绪`并勾选`可领取`，回到公共队列。
- 需用户判断：Agent 只写工程验收结果，将`负责人`改为`用户`并保留在待验收链；不代替用户作视觉或交互结论。
- 发生阻塞：把`状态`改为`阻塞`，在`阻塞原因`写可验证的事实、解除条件和需要谁行动。

`验收证据`每次至少包含：受影响行为、精确命令与结果、已检查的可见路径、未运行项、剩余风险和下一个负责人。更新后必须重读记录，确认证据、状态和负责人已持久化，最后才在聊天中发送简短通知。

## 临时 Subagent

临时 Subagent 不从公共队列领取新任务，也不成为 Teable 主任务的新负责人。

- 父 Agent 必须先领取 Teable 任务，再分派 Subagent。
- 分派必须给出 Teable 任务编号/记录、子范围、禁区、完成判据和交回对象。
- Subagent 在读代码或写文件前，必须亲自读取父任务及其链接的验收/ADR。无法访问 Teable 时是阻塞，不靠猜测继续。
- Subagent 只交回文件变更、精确命令结果、未验项和风险。父 Agent 负责整合、复核、解决冲突和写回 Teable。

## 表格如何保持可复利

- 视图按任务生命周期命名，不按 Agent、模型或工具命名。
- 一类事实只写在一个字段；不为不同 Agent 复制范围、验收或证据字段。
- 身份变化只扩展`负责人`的可选值，流程变化才允许修改状态或公共视图。
- 新字段或视图必须回答一个现有字段/视图无法回答的持久问题；否则不新增。
- 当流程变更时，先改 Teable 字段/视图及本文，再改其他 handoff 或自动化。历史执行快照不回写成新规则。
