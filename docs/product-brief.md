# 产品简报：边读边说，思想关系接通后世界生长

> 状态：产品方向裁决 / MVP 合同
> 版本：0.4 / 2026-08-09
> 阅读范围：Cannan 版《国富论》Books I–V（两卷）；首批可执行机制仍限定于 Book I, Chapters I–III 的两份受审配方
> 当前原型边界：Godot 价格上限场景只是视觉与点击运行的 placeholder，不代表最终针厂经济机制。

## 1. 先看一次具体体验

读者不是先打开一个游戏，再回来读书。她从书页中的两个想法开始，让世界在它们之间长出来。

1. 她读到**PDF 第 36 页**关于分工的段落，按住耳机说：“如果大家各做一道工序，熟练度会提高，但我还不知道这是不是总有用。”页码只是显示位置，事实身份是 `smith.b1.c1.p1`，`smith.b1.c1.division` 只是兼容别名。
2. 书页边缘留下一个小便签：这是她的 Idea，旁边仍然看得见原文、章节和她自己的话。系统没有替她判对错。
3. 她继续读到**PDF 第 45 页**关于市场范围的段落，又说：“市场太小的话，专门做一道工序的人可能卖不掉自己的产出。”事实身份是 `smith.b1.c3.p1`，`smith.b1.c3.market_extent` 只是兼容别名。
4. 第二张便签出现。Agent OS 提出一条带证据、可编辑的关系，并把当前 `BookThought` 与读者的两张 `ReaderIdea` 分开显示：“你正在把‘分工提高能力’和‘市场范围限制分工’放进同一条关系里。”她可以改写、拒绝或暂不确认。
5. 当两段文字和她的关系都确认、`PlayabilityGate` 通过后，她可以主动选择麦克风说：“已经可以玩了。”主动语音邀请只在此后出现；不接受麦克风也可以继续文字操作。
6. 两段原文之间展开一个小世界：一间针厂、几道工序、有限订单和一条运输路线。它不是从页面跳出去的旁挂窗口，而是从两段文字中间生长出来的 Inline World Block。
7. 她先让工人高度专业化，再把市场范围缩小。产量可能上升，但库存、等待、现金压力或断供也出现。她可以随时停止、重试或换一个办法。
8. 试玩结束，世界折回书页。两张便签、她最初的预测、发生过的结果和 Smith 的两段原文并列出现；她能指出哪一步来自自己的想法，哪一步是世界在无人计划时产生的后果。

这就是产品的最小承诺：**读者先留下自己的 `ReaderIdea`；Agent OS 以阅读陪伴者、原文守护者、世界机制导演三种身份在来源约束内回答、保留可修订的 `BookThought`、允许有产出的联想并温和回引真正无关输入，再从已确认关系编译机制；关系与 PlayabilityGate 通过后世界才生长，数值后果始终由确定性的 `WorldKernel` 决定，结果必须回到原文。**

## 2. 为谁做、解决什么问题

### 2.1 首要读者

- 17–23 岁、高中高年级或大学低年级；
- 非经济学专业；
- 听过“分工提高效率”和“看不见的手”，但没有读过或读不进原著；
- 中文阅读为主，愿意通过短切片、语音和可见结果进入经典文本。

他们缺的不是一段更短的摘要，而是把二手标签变成可操纵、可失败、可回放的因果链。现有阅读摩擦研究表明，18 世纪语言、篇幅、译本和二手 Smith 标签让读者进不去；即使记住“分工”“市场范围”，也未形成动态模型。详见 [《国富论》读者阅读摩擦研究](../research/wealth-of-nations-reading-friction.md)。

### 2.2 首版只追一个窄问题

首版不试图解决所有 Smith 解释争议，只让读者亲自回答：

1. 分工为什么可能提高生产率？
2. 交换如何让分工继续发生？
3. 为什么分工受市场范围限制？
4. 为什么这三件事不能直接等同于“市场永远正确”，也不能直接冒充 Book IV 的特定 “invisible hand” 语境？

## 3. 用户会看到什么

### 3.1 书页上的三个位置

**阅读态**：原文占主位。每个段落有一个页边编号、章节和短释义；点击或说话会在段落旁留下便签。页面显示“已接通的段落”和“还缺哪一段”，不先显示游戏。

**世界态**：当至少两段文字的关系被读者确认、证据和确定性运行条件通过 `PlayabilityGate` 后，纸面才扩大成可玩的世界。Gate 之前只显示阅读/审阅状态，不显示可执行世界或主动语音邀请。左缘仍留着两段原文的名字和关系箭头，世界画面占主要视线；底部明确写着 `MODEL EXTENSION`。这是目标合同，当前视觉原型的按钮可用不等于 Gate 合同已实现。

**证据态**：试玩后世界缩回，结果按原来的两段文字归档：我的预测、发生了什么、哪一条关系把它们接起来、Smith 原文写了什么、我们为了运行增加了什么。按钮写“回到原文继续读”。

### 3.2 语音行为

语音是读者主动打开的一条路，不是自动陪聊：

- 首次阅读不开麦，不把授权当入场券；
- 读者说完一句才形成一个可编辑的 Idea，没说完的临时字幕不会改变世界；
- 世界真正可玩并且读者同意后，Agent 才能邀请主动语音；
- 读者随时可以说“停”或按停止，正在播放的解释立即结束；
- 权限被拒、设备/浏览器不支持、ASR 低置信或无法确认来源时，页面显示可恢复的文字/重说入口，不把未知当成动作；
- 停止会结束采集/播报但保留已经提交的 Idea 和世界事实；
- 语音断线时，页面保留已经写下的便签和结果，可重试或改用文字；
- 不愿使用语音的人，仍能完成阅读、关系确认、试玩和回放。

### 3.3 Agent 做什么、不做什么

Agent OS 在同一轮同时承担三个边界清楚的身份：

| 身份 | 用户可感知的工作 | 目标合同中的权限边界 |
|---|---|---|
| 阅读陪伴者 | 在当前 `SourceBlock` 上回答问题、复述读者理解，提出带证据、置信度和 `open_question` 的可修订 `BookThought`。 | 不能替读者发明/改写 `ReaderIdea`，不能把推断说成 Smith 原话，也不能因回答改变 `WorldState`。 |
| 原文守护者 | 核对版本、锚点、证据和相关性；保留能照亮机制的 `productive_detour`，对真正无关输入给一个具体、非惩罚性的 soft-return。 | 不能以“偏题”压制联想；读者拒绝回引后不重复邀请、不创建领域事实。 |
| 世界机制导演 | 从已确认关系中选择/编译机制，解释 allowlist 动作的前置条件，按局部状态安排角色观察和因果呈现顺序。 | 只能提出结构化动作/观察候选；不能直接写钱、库存、订单、角色状态或把角色写成脱离事件的聊天 NPC。 |

共同不变量：LLM 只生成 schema-valid 候选，所有世界数值由确定性的 `WorldKernel.decide/evolve` 产生并由 `EventStore` 记录；`ReaderIdea` 与 `BookThought` 并列显示，关系/机制在用户 review/commit 前不能进入世界。上述是目标合同，尚未被当前 placeholder 自动证明。

## 4. 书与世界的内容边界

### 4.1 三个连续的思想块

首版用稳定的语义标签连接三段文字。页码只作显示，不能成为永久身份。

| 语义标签 | 章节 | 读者要抓住的思想 | 体验中的便签标题 |
|---|---|---|---|
| `smith.b1.c1.p1`（alias: `smith.b1.c1.division`） | Book I, Chapter I | 分工通过熟练、减少切换和机器提高生产率 | 专业化会带来什么？ |
| `smith.b1.c2.exchange` | Book I, Chapter II | 交换把不同人的需要接起来；屠夫/酿酒师/面包师段落属于这个语境 | 我怎样得到自己没有的东西？ |
| `smith.b1.c3.p1`（alias: `smith.b1.c3.market_extent`） | Book I, Chapter III | 没有足够市场，分工不能无限细化 | 谁来买走这道工序？ |

原文、译文和诚实释义必须分层显示。若使用中文概括，明确写“释义”，不把它放进引号冒充原句。

### 4.2 针厂世界的最小边界

试玩目标是一间小针厂/小工坊，先固定四个可观察角色：牧羊人、纺纱工、织工、商人。

- 允许的最小变量是市场可触达订单、交换是否开放、运输成本、库存、订单、现金和专业化深度；
- baseline 中 `reachable_orders < weaver.minimum_orders_for_next_depth + weaver.outputs_pending`，织工请求再专业化必须拒绝并保留原因；
- 读者明确说“扩大市场”后，只改变 allowlist 内的市场变量；订单、交换路径和角色行动按 merchant → shepherd/spinner → weaver 的局部状态顺序由 `WorldKernel` 演进；
- 同一 graph revision、seed、ruleset 和动作序列必须可重放；每个关键数字都回到事件账目；
- Book V Chapter I 的劳动者认知代价留作后续边界，不伪造心理诊断。上述是 MVP 目标合同，不把当前 Godot placeholder 的按钮变化当作已实现机制。

这个世界不是现代经济预测器，也不是整本《国富论》的仿真。所有超出原文的规则都写 `MODEL EXTENSION`，所有当代争议写 `MODERN CAVEAT`。

### 4.3 不把不同文本混成一句话

- Book I, Chapter II 的晚餐/面包师段落：谈交易时诉诸对方利益、交换如何接通不同目的；
- Book I, Chapters I–III：本首版的分工—交换—市场范围连续关系；
- Book IV, Chapter II 的 “invisible hand”：特定贸易/资本语境，不能被冒充成晚餐段落或针厂的普遍定理。

证据页要把这些位置分开，避免“Smith 认为市场总会自动正确”的新神话。

## 5. 最小试玩合同

### 5.1 必须发生

1. 读者至少留下两个来自原文旁的 `ReaderIdea`；
2. 阅读陪伴者提出带证据、置信度和可修订记录的 `BookThought`，与 ReaderIdea 并列显示；
3. Agent OS 提出一条可编辑、带 typed edge 的机制关系，读者确认/拒绝/修改；未确认前不提交；
4. 关系、证据、Kernel 可回放条件和用户控制全部通过 `PlayabilityGate` 后，段落之间才长出世界；
5. 小市场下“让织工再专业化”产生可解释拒绝；读者随后以语音或文字“扩大市场”，角色按因果顺序反应，数值只由 `WorldKernel` 改变；
6. 结果回到 PDF 36 ↔ PDF 45，并保留读者预测、`BookThought` 修订和世界事件；
7. 读者可以 Stop、Retry、继续文字；权限拒绝、ASR unknown、无来源、跑题回引被拒等失败不抹掉已确认记录。

### 5.2 明确不做

- 不把本书的确定性两卷构建管线扩张为通用 PDF/HTML/EPUB 产品或万能 parser；
- 不做 chat-first 首页或“和 Adam Smith 聊天”；
- 不做任意宏观政策沙盘、无限世界编辑器；
- 不做每轮自由调用模型的 20 个 NPC；
- 不让模型直接改变世界状态或把模型输出当事实；
- 不把 Godot 价格上限 placeholder 当最终机制，不擅自改变经济机制内容；
- 截至 2026-08-07，第一方公开页面无法确认 2 或 5 分钟要求；用户提供的章程副本写复赛视频 ≤2 分钟、路演总时长 ≤4 分钟，但这不是在线第一方证据。因此项目按 2 分钟作为保守核心闭环设计约束，不宣称官方规则；
- 不在没有用户对照实验前声称“语音一定比文字更好”或“多 Agent 一定更好”。

## 6. 两分钟核心闭环（保守设计约束，不宣称官方规则）

截至 2026-08-07，第一方公开页面无法确认 2 或 5 分钟要求；用户提供的章程副本写复赛视频 ≤2 分钟、路演总时长 ≤4 分钟，但这不是在线第一方证据。以下按 2 分钟作为保守核心闭环设计约束，验证叙事是否成立，不把 2 分钟写成官方时长声明。

| 相对时间 | 用户看到/做什么 | 证明什么 |
|---|---|---|
| 0:00–0:15 | 读 PDF 36 的分工段落，语音留 `ReaderIdea` | 原文先于世界，读者拥有第一句话 |
| 0:15–0:30 | 页边出现第一张便签；读 PDF 45 的市场范围段落，留第二个 `ReaderIdea` | 两次理解和 source IDs 都被保留，可回到原文 |
| 0:30–0:45 | Agent OS 提出带证据的关系与 `BookThought`；读者修改或确认 | 三种身份各司其职，关系仍停在 review，未静默 commit |
| 0:45–0:55 | 读者说“已经可以玩了”并同意邀请 | 语音邀请发生在关系确认和可玩性之后 |
| 0:55–1:20 | 两段文字之间长出针厂；读者运行专业化方案 | 世界来自阅读关系，而不是旁挂游戏 |
| 1:20–1:35 | 先让织工再专业化（baseline 拒绝），再说“扩大市场”并观察角色 | refusal → market/order path → local character reactions；数值由 Kernel 决定 |
| 1:35–1:52 | 试玩停止，结果折回两段原文 | 事件、预测和原文能互相定位 |
| 1:52–2:00 | 读者继续读或再次说话 | 阅读没有被一次 demo 终止 |

若后续获得可核验的第一方规则，再按其重排节奏；当前不把任何时长数字写成官方产品承诺，也不修改产品的因果主链。

## 7. 成功标准与验收

### 7.1 读者理解

目标读者完成一次体验后，应能根据自己的便签和结果回答：

1. 分工为什么改变了产出？是熟练、少切换，还是瓶颈变化？
2. 为什么同一分工关系在小市场下会卡住？
3. 交换如何让陌生人的不同目的接通？
4. Book I 的晚餐/面包师段落与 Book IV 的 invisible hand 段落哪里不同？
5. 这次试玩加入了哪些 Smith 原文没有声称的简化？

### 7.2 可观察验收

- 原文、便签、关系箭头、世界和结果页在浏览器主链中真实可见；
- `ReaderIdea` 与 `BookThought` 在页面上可区分，旧 revision 被标为 superseded/stale 而不是覆盖历史；
- 两次 Idea 丢失、语音中断、权限拒绝、模型超时或关系不确定时，用户仍知道下一步；
- 同一初始状态和同一关系重跑得到相同结果；
- 关键库存、现金、工时和订单变化都能回到结果账目；
- 小市场织工拒绝、扩大市场后的 merchant → shepherd/spinner → weaver 因果观察均能被用户看到；
- 明显无关输入只得到一次具体 soft-return，用户拒绝后不再重复邀请；
- 页面能指出真实原文、读者关系和世界结果，不能只有一段 Agent 解释；
- 5 名以上目标读者任务测试（含至少 1 名赛事要求的真实读者）在产品实际允许时执行；不得伪造用户反馈。

## 8. 当前状态与下一步

当前仓库包含真实 PDF compositor、A/B/C 页面壳、语音/文字/Replay 入口和 Godot 价格上限 placeholder；这些是原型表面与回归对象，不自动证明三身份 Agent OS、BookThought 生命周期、角色拒绝/因果反应、soft-return 或持久化合同已经实现。Prototype V2 的每一项都必须用本轮浏览器证据标记通过、失败或未实现。

下一步顺序：先以 PDF 36 → PDF 45 的固定 fixture 补齐三条 Agent OS 验收路径（正常讨论；织工拒绝 → 语音扩大市场 → 角色反应；跑题回引 → 拒绝不重复），再接生产语音和文档格式，不先扩大到整本书或多 Agent。

## 9. 产品风险

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 读者只点按钮、不读段落 | 关系完成得很快，但说不出原文 | 原文和便签占主位，Agent 必须指出两段依据 |
| 语音变成打断式陪聊 | 用户关麦后无法继续 | 明确邀请、Stop、文字 fallback；未确认关系不邀请 |
| Agent 讲得像真的但没有经历 | 结果页只有解释，没有具体事件 | 用可见账目和重跑结果约束说明 |
| 世界抢走书的主角位置 | 世界常驻、来源消失 | 只在关系、证据与 Kernel 条件通过 `PlayabilityGate` 后生长；收起/重开必须回到同一原文 |
| Agent 身份过窄或越权 | 被缩成命令解析器，或解释被当成世界事实 | 明示阅读陪伴者、原文守护者、世界机制导演；LLM 只提候选，数值只由 `WorldKernel` 决定 |
| 经典被现代模型冒充 | 用户以为价格上限是 Smith 原实验 | 分开标记原文、模型扩展、现代边界 |
| 范围膨胀 | 同时做整本书、PDF、20 个 Agent | 每次只增加一条可验证的段落关系 |
