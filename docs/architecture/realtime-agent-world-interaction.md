# 实时 Agent 世界生成与开放交互机制

> 状态：Accepted 架构合同 / T069（用户 2026-08-10 确认 ok）；空间主交互执行细节以 walkable-world-embedding.md 为准
> 版本：0.4 / 2026-08-10
> 范围：Living Reader 可执行世界的生成、扩展、行动与回流
> 权威关系：补充 `design.md`、`CONTEXT.md`、`agent-os-behavior-protocol.md`、`event-protocol.md`；不替换 EventStore / WorldKernel 写入合同

本文回答三个问题：

1. 世界哪些部分可以预制，哪些必须由 Agent 实时生成。
2. 读者、Agent、校验层、确定性内核和呈现层如何交互。
3. “开放”在产品里具体指什么，用户如何看见它。

## 1. 一句话结论

**预制的是受审原语和安全规则；实时的是围绕当前原文与读者问题的世界组合、行动候选和增量扩展。**

它既不是提前写好的完整小游戏，也不是 LLM 任意生成代码或直接改经济状态。

```text
预制层                实时层                     事实层
--------              ------                     ------
经济原语              WorldIntent                EventStore
规则能力              WorldPlan / Patch          WorldKernel
资产语法              ActionCandidate            DomainEvent
安全预算              PresentationPlan           Evidence
PlayabilityGate       角色观察与解释             exact replay
```

## 2. 参考视频观察（用户指定）

视频：`素材管理/人到达有多懒才想起来要做这个功能 [6a74629400000000210223c1].mp4`
时长：15.8s；抽帧：`/tmp/living-reader-reference-6a746294/frame-01.png` 至 `frame-08.png`

| 时段 | 可见行为 | 开放感来自哪里 |
|---|---|---|
| 0–2s | 顶视角地图；分叉走廊与房间；自由移动；地上可拾取物；冷却/HP/等级 | **空间可探索**，不是一条固定流水线 |
| 2–6s | 遭遇敌人后进入战斗；双方 HP；技能条；战斗记录 | **情境从移动中涌现**，不是点两个预制按钮 |
| 6–14s | 治疗/攻击技能、伤害数字、胜负结算、掉落与记录更新 | **系统连锁 + 即时反馈 + 时间继续** |
| 全程 | 同一会话内地图与战斗连续切换 | 世界在继续，不是一次性演示动画 |

对 Living Reader 的可迁移原则：

- 开放感来自空间、选择、连锁后果和持续时间，不来自“更精致的四站贴图”。
- 预制可以是角色/物件/规则原语；**布局、遭遇、可选行动、反馈文案**应随当前问题与状态生成或解锁。
- 用户必须始终看见：我在哪、我能做什么、刚才发生了什么、它和书有什么关系。

不可照搬：

- 以战斗成长为核心的 Roguelike 目标。
- 与原文无关的无限刷怪地图。
- 把 Living Reader 做成通用沙盒编辑器。

## 3. 现状证据：已有能力与偏差

### 3.1 已经正确的骨架

| 能力 | 证据 | 应继承 |
|---|---|---|
| Agent 只产候选 | `handleAgentTurn` + Bun `propose_candidate` | LLM 不写事实 |
| 邀请零写入 | `mode=invite_world` 只生成 `AgentWorldInvitation` | 读者接受前不改世界 |
| 唯一写入路径 | `ReaderWorldUseCase` / `dispatch` → EventStore | 保持 |
| 确定性后果 | `WorldKernel.decide/evolve` | 数值只由内核决定 |
| 呈现与规则分离 | `compilePresentation` → `PresentationPlan` → `InlineWorldBlock` | DOM/CSS 只渲染计划 |
| 来源门禁 | recipe 必须 reviewed，且 source 匹配 | 未受审机制不能进世界 |

### 3.2 当前把“实时/开放”做窄的地方

| 现状 | 代码/内容证据 | 产品偏差 |
|---|---|---|
| 只有 2 份完整配方 | `division-deepening.json` / `market-extent.json` | Agent 只能点菜，不能组菜 |
| 邀请只选 `recipe_id` | `AgentWorldInvitation.recipe_id` | 实时层停在“选关”，不是“生成计划” |
| 动作 hardcode 两个 | `deepen_specialization` / `expand_market` | 行动空间不可随问题扩展 |
| 场景模板固定线性工坊 | `scene_template: "wool-workshop"` + 固定 `entity_order` | 空间不可探索，只是四站流水线 |
| 原型罐头动作 | `prototypes/one-bit-wool-town` 的开拓市集/织工赶单 | 看起来像预制小游戏 |
| InlineWorld 未成为主路径一部分 | 组件齐全但产品树挂载仍不完整 | 机制正确性无法在主 UI 被用户感知 |

结论：

- **实时**今天只覆盖“何时邀请 / 是否执行 allowlist 动作”。
- **开放**今天几乎不存在；用户看到的是封闭配方演示。
- T068 美术重绘不能补这个洞；先定机制，再定下一版 D007 原型范围。

## 4. 领域对象：预制 vs 实时

### 4.1 预制层（Reviewed，可版本化，可回放）

| 对象 | 含义 | 例子 | 谁写 |
|---|---|---|---|
| `EconomicPrimitive` | 受审经济积木 | 角色类型、库存、订单、运输、专业化深度 | 人审内容 + 规则代码 |
| `RuleCapability` | 内核可执行的规则能力 | `expand_reachable_market`、`attempt_deeper_specialization` | WorldKernel / ruleset |
| `AssetGrammar` | 呈现可用的视觉/动作词汇 | 角色外轮廓、站点类型、motion verb、音效槽 | 设计与内容 |
| `SafetyBudget` | 生成与扩展边界 | 最大实体数、最大动作数、禁止无来源机制 | 架构合同 |
| `ReviewedMechanismSeed` | 可选的受审机制种子，不是完整关卡 | “市场范围约束分工”的最小可运行核 | 内容评审 |

预制层**禁止**包含：

- 完整关卡脚本当唯一世界。
- 固定“四个站点 + 两个按钮”冒充全部可玩性。
- 未带来源与模型扩展边界的自由剧情树。

### 4.2 实时层（每轮由 Agent 提议，代码校验）

| 对象 | 含义 | 必须携带 | 谁写 |
|---|---|---|---|
| `WorldIntent` | 为什么现在要开/扩这个世界 | `source_ids`、读者问题、机制假设、成功观察 | Agent 候选 |
| `WorldPlan` | 首次进入前的可审阅构图 | 空间节点、角色、资源、初始动作、ModelExtension、失败态 | Agent 候选 + 确定性补全 |
| `ExecutableWorldPatch` | 对已存在世界的增量修改 | 新增/解锁的地点、角色、动作、约束；basis revision | Agent 候选 |
| `ActionCandidate` | 当前状态下可尝试的行动 | 前置条件、预期观察、来源依据、风险级别 | Agent 或规则投影 |
| `CharacterObservation` | 角色对已发生局部事实的解释 | world_revision、事件引用、局部状态 | 导演编排，不编造事实 |

### 4.3 与既有术语的关系

| 既有术语 | 关系 |
|---|---|
| `WorldRecipe` | 降级为**受审机制种子 / 原语打包格式**，不再被解释成“完整预制游戏”。长期可演进为 primitive bundle。 |
| `WorldPatch`（CONTEXT 原义） | 继续表示阅读图（想法/关系）变更；可执行世界增量使用 `ExecutableWorldPatch`。 |
| `MechanismGraph` | 仍是关系与机制编译边界；`WorldPlan` 必须能回溯到 committed graph edges。 |
| `PresentationPlan` | 仍是渲染合同；改为由 `WorldPlan`/当前 `WorldState`/事件编译，而不是只读死配方模板。 |
| `AgentWorldInvitation` | 升级为携带 `WorldIntent` + `WorldPlan` 摘要；不能只剩 `recipe_id`。 |

## 5. 权限矩阵

| 层 | 可以做 | 不可以做 |
|---|---|---|
| 读者 | 提问、接受/拒绝邀请、行动、停止、回到原文、要求解释 | 直接改 EventStore；绕过来源门禁 |
| 阅读陪伴者 | 回答、提出 BookThought、解释世界与原文关系 | 发明 ReaderIdea；把推断写成 Smith 原话 |
| 原文守护者 | 校验来源/版本/相关性；标记不确定 | 用“偏题”压制有产出的类比 |
| 世界机制导演 | 生成 WorldIntent/Plan/Patch/ActionCandidate；编排观察顺序 | 写现金/库存/订单；生成任意代码；无事件的角色小说 |
| Policy Gate | 校验来源、能力 allowlist、预算、basis、前置条件 | 发明新机制；静默改计划 |
| Recipe/Plan Compiler | 把通过的计划编译为 kernel commands + PresentationPlan | 引入未校验字段；读 DOM/时间/随机 |
| WorldKernel | 唯一决定数值后果与角色局部状态转移 | 解释文本；决定 UI 文案 |
| Presentation | 按计划渲染空间、动作、反馈、a11y 摘要 | 私自改状态；用动画假装后果 |
| EventStore | 唯一事实源与 exact replay | 被 LLM 直接写入 |

## 6. 端到端状态机

```text
Reading
  │ 读者围绕 SourceBlock 提问/表达
  v
Discuss / Clarify
  │ 陪伴者回答；守护者核验；可形成 ReaderIdea / BookThought / RelationProposal
  v
Relation Review
  │ 用户确认关系后，才具备 invitation_basis
  v
World Intent Draft          ← Agent 实时
  │ 生成 WorldIntent（来源、问题、机制假设、预期观察）
  v
World Plan Draft            ← Agent 实时 + 确定性补全
  │ 生成可审阅 WorldPlan（空间、角色、资源、动作、扩展边界）
  v
Policy Gate
  │ 来源匹配？能力 allowlist？预算？graph 仍当前？PlayabilityGate？
  ├─ fail → 可见说明，零世界写入，回到 Discuss
  v
Invite (zero write)
  │ 展示：要验证的问题、将出现的空间/角色、规则边界、ModelExtension、可返回路径
  v
Reader Accept / Decline
  ├─ decline/snooze → 不写入，可继续阅读
  v
Compile & Seed
  │ 确定性编译 → world.seeded + 初始 PresentationPlan
  v
Playable World
  │ 空间可看可点；当前 ActionCandidate 可见；时间/状态可继续
  ├─ Reader Act / Agent-proposed Act
  │     Gate → Kernel → DomainEvent → Presentation 更新 → Companion 解释
  ├─ Reader Ask “为什么/然后呢”
  │     可生成 ExecutableWorldPatch 提案（扩地点/角色/动作），再次确认后增量编译
  ├─ Stop / Collapse
  │     保留已提交事实；回到 SourceBlock
  v
Evidence
  │ 想法 → 关系 → 计划/扩展 → 事件 → 原文
```

### 6.1 关键不变量

1. **邀请零写入**：Intent/Plan 预览不得 seed 世界。
2. **确认边界分层**：
   - 首次进入世界：必须读者接受邀请。
   - 低风险、清晰、可逆、已在当前 plan allowlist 内的动作：可直接执行。
   - 改变世界边界的 `ExecutableWorldPatch`（新地点/新角色类型/新规则假设）：必须再次可见确认。
3. **LLM 永不写 WorldState**。
4. **同一 plan revision + seed + ruleset + action 序列 = exact replay**。
5. **Stop 真停止**：停止采集/播报/待确认提案；已提交事件保留。

## 7. 开放的四个维度（用户如何看见）

“开放”在本产品中**不是**无限地图编辑器，而是书本约束下的四类可观察开放性：

### 7.1 空间可探索

用户看见：

- 不只一条 `A→B→C→D` 工位。
- 至少有可区分的地点节点（牧场/工坊/仓房/道路/市集等），可查看、可切换焦点。
- 地点上有可见的人、物、压力（积压、缺货、在途）。
- 移动/聚焦本身可改变“当前可行动作”，不必先点全局大按钮。

首版最小形态：

- 拓扑图 + 地点详情，不必先做自由像素漫游。
- 但**禁止**再用单一水平四站条冒充“世界”。

### 7.2 行动可生成

用户看见：

- 当前行动列表随地点、角色状态、读者问题变化。
- Agent 可以提出新的 ActionCandidate，但必须显示前置条件与来源。
- 失败行动也有可见原因（市场太小、原料不足、交换未开）。

首版最小形态：

- 每轮从规则能力中投影 1–3 个当前可行动作。
- Agent 可建议“下一步最值得试哪个”，不能脱离 allowlist 发明数值效果。

### 7.3 系统会连锁

用户看见：

- 一个行动改变多个局部状态（订单↑ → 纱线需求↑ → 织工态度变化 → 现金/库存变化）。
- 角色观察按因果顺序出现，且能点回事件与原文。
- 二阶后果不是旁白硬说，而是状态与事件可核对。

### 7.4 时间会继续

用户看见：

- 世界有 `seeded / running / paused / evidence_ready` 等阶段。
- 收起后再打开，状态仍在；不是每次重播开场动画。
- 追问可以在**同一个 world_id** 上打补丁，而不是另开一个无关小游戏。

## 8. 端到端例子：《国富论》

### 8.1 第一轮

读者在 `smith.b1.c3.p1` 问：

> “如果只能卖给附近村子，织工为什么不肯再细分？”

Agent 不应直接丢一个固定羊毛镇罐头，而应实时形成：

**WorldIntent**

- 来源：`smith.b1.c3.p1`（+ 可选 `smith.b1.c1.p1`）
- 问题：小市场如何抑制分工深化
- 假设/ModelExtension：织工需要最低可触达订单才肯提高 specialization_depth
- 预期观察：小市场下深化被拒；扩大市场后态度变化

**WorldPlan（首次）**

- 地点：`village_market`、`workshop`、`storehouse`、`lane_to_town`（lane 先锁）
- 角色：weaver、spinner、shepherd、merchant
- 初始压力：reachable_orders=2，stock 偏高，weaver stance=waiting/refusing
- 当前动作：
  - 查看织工顾虑
  - 尝试深化分工（预期失败）
  - 让商人探路（解锁扩市场的前置）
- 明确边界：不是现代物流模拟；数值是思想实验

读者接受后，世界在两段原文之间展开。读者先“尝试深化分工”→ Kernel 产出拒绝事件 → 织工观察解释“再细也卖不完”→ Evidence 指回市场范围原文。

### 8.2 第二轮追问（同一世界）

读者说：

> “那如果修到隔壁镇的路呢？”

Agent 生成 **ExecutableWorldPatch**：

- 解锁 `lane_to_town` 与 `town_market`
- 新增动作 `open_town_exchange`
- 不重置库存/现金；basis 绑定当前 world_revision
- 说明 ModelExtension：道路降低交换摩擦，提高 reachable_orders

读者确认补丁 → 编译增量 → 地图多出城镇方向 → 执行开通交换 → 订单、原料需求、织工态度连锁变化 → 可再问“这和第一段分工的好处怎么连起来？”并回到 `smith.b1.c1.p1`。

这才是实时 Agent 交互：  
**同一世界被读者问题推进，而不是换一份预制剧本。**

## 9. 实时语音在闭环里的位置

**实时语音是入口与口述通道，不是世界生成器，也不是事实写入器。**

```text
你开口 / 打字
   │
   │  实时语音只负责：
   │  - 听清并给出 final 转写
   │  - 低延迟口头回应
   │  - 停止、打断、权限失败的可见状态
   v
同一个 Agent 语义回合（文字 final 与语音 final 等价）
   │
   │  这里才生成：
   │  WorldIntent / WorldPlan / ActionCandidate / ExecutableWorldPatch
   v
Policy Gate + 确定性编译 + WorldKernel + EventStore
   │
   v
画面更新；Agent 可用语音把结果说给你听
```

硬边界：

1. 只有 **final** 语音转写才能进入共享 Agent 回合，或形成 `ReaderIdea`。半句、噪音、低置信转写不能改世界。
2. 语音和文字走**同一套**语义回合与权限，不存在“语音专用后门”。
3. 实时语音**不能**直接改钱、库存、订单、角色状态，也不能直接 seed 世界。
4. 没有麦克风时，整条闭环必须仍可用纯文字完成。
5. `停止` 必须立刻停采集/播报；已写入的世界事实保留，未确认的邀请或补丁作废。

因此：

- “实时交互”= 你用语音/文字持续推动**同一个**语义闭环；
- “实时生成”= Agent 在该闭环里当场组成计划与补丁；
- 二者相关，但**不是**“有语音就等于世界在实时生成”。

## 10. 中文术语表（不允许模糊）

下列每个词都有且只有一个意思。括号中的英文是代码/文档内部名，对用户界面不是必需文案。

### 10.1 书与读者

| 中文名 | 内部名 | 精确定义 | 不是什么 |
|---|---|---|---|
| 来源块 | SourceBlock | 书里一段稳定、可引用、可回跳的正文单位。身份靠语义 ID，不靠页码。 | PDF 页、屏幕截图、临时高亮 |
| 来源锚点 | SourceAnchor | 来源块内部更精确的位置，用来挂想法或证据。 | 模糊的“大概在这页” |
| 读者想法 | ReaderIdea | 你自己说出来/写下来的观察、问题、假设、反对或类比。归属永远是你。 | Agent 替你总结后的“正确答案” |
| 书籍思考 | BookThought | Agent 基于原文提出的、可修订的理解，分引文/推断/实验三类。 | 你的想法；隐藏思维链 |
| 关系候选 | RelationProposal | Agent 提出的“这两处思想可能如何相连”，尚未算数。 | 已确认事实 |
| 关系边 | RelationEdge | 你确认后的关系。只有它能参与世界编译。 | 未确认的相似推荐 |

### 10.2 预制与实时

| 中文名 | 内部名 | 精确定义 | 不是什么 |
|---|---|---|---|
| 经济原语 | EconomicPrimitive | 预先审过的积木：角色类型、库存种类、订单、运输、专业化深度等。 | 一整关游戏 |
| 规则能力 | RuleCapability | 内核真正会算的动作能力，例如“扩大可触达市场”“尝试更深分工”。 | 任意自然语言命令 |
| 资产语法 | AssetGrammar | 画面可用的视觉/动作词汇：角色外轮廓、地点类型、运动动词、音效槽。 | 完整关卡美术包 |
| 安全预算 | SafetyBudget | 生成上限与禁区：最多多少地点/角色/动作，禁止无来源机制等。 | 事后再补的宽松提示 |
| 受审机制种子 | ReviewedMechanismSeed | 可选的最小机制核，证明某条书中规律可运行。今天的 `WorldRecipe` 应被理解成它。 | 预制完整小游戏 |
| 世界意图 | WorldIntent | 本轮为什么要开/续这个世界：对应哪段原文、你的哪个问题、要检验什么假设、预期看到什么。 | 已经可玩的关卡 |
| 世界计划 | WorldPlan | 首次进入前可审阅的构图：有哪些地点、谁在场、有哪些资源、现在能做什么、失败会长什么样、哪些是模型假设。 | 渲染截图；最终数值状态 |
| 可执行世界补丁 | ExecutableWorldPatch | 对**已经存在**的同一世界做增量修改：解锁地点、加人、加动作、加约束。保留旧事实。 | 另开一局；阅读图上的关系补丁 |
| 行动候选 | ActionCandidate | 当前这一刻你可以尝试的一个具体行动，带前置条件、预期观察、来源和风险级别。 | 没有状态效果的电影按钮 |
| 模型扩展 | ModelExtension | 原文没写死、但世界要跑起来必须补的假设，且必须标明“这是模型假设”。 | 作者原话；隐藏规则 |

### 10.3 事实、画面与回流

| 中文名 | 内部名 | 精确定义 | 不是什么 |
|---|---|---|---|
| 世界状态 | WorldState | 可回放的经济事实：订单、库存、现金、角色局部状态等。 | Agent 嘴上说说的剧情 |
| 领域事件 | DomainEvent | 一次已提交的事实变化记录，是唯一历史。 | UI 动画；临时 toast |
| 事件库 | EventStore | 唯一事实源。所有恢复、回放、证据都从这里来。 | 浏览器临时内存 excels |
| 世界内核 | WorldKernel | 唯一计算数值后果的确定性引擎。 | LLM；前端动画 |
| 呈现计划 | PresentationPlan | 给画面层的纯数据说明：现在有谁、在哪、播什么动作、读什么摘要。 | 自己改状态的渲染器 |
| 角色观察 | CharacterObservation | 角色对**已经发生**的局部事实的解释。 | 没有事件支撑的 NPC 闲聊 |
| 证据块 | EvidenceBlock | 把行动、后果、原文、模型假设串起来的可核对回放。 | 分数板；一句总结 |
| 可玩性门禁 | PlayabilityGate | 世界是否真有可理解选择、可见后果、可回来源；不通过就不开放。 | “页面没报错就算可玩” |

### 10.4 两个容易混的“补丁”

| 中文名 | 内部名 | 改的是什么 |
|---|---|---|
| 阅读图补丁 | WorldPatch | 你的理解网络：想法、关系、解释。 |
| 可执行世界补丁 | ExecutableWorldPatch | 已经开跑的经济世界：地点、角色、动作、约束。 |

二者名字相近，但**绝不是同一对象**。

### 10.5 下一版原型三个靶心（指哪打哪）

这三项是下一版必须让你在屏幕上直接看见的东西，不是形容词。

#### A. 地点拓扑

**定义：** 世界由多个可区分的**地点节点**和它们之间的**连接**组成；你能知道自己在看哪里，并能把焦点切到另一处。

**最小可见形态：**

- 至少 3 个地点，例如：`村落市集`、`工坊`、`仓房`；可另有一个锁定中的 `通往邻镇的路`。
- 每个地点能看出：谁在这、有什么货、当前压力（缺货/积压/等待）。
- 点击/点选地点会改变“当前焦点”，从而改变下方可做的事。

**明确不是：**

- 一条从左到右的四站流水线，只能顺着看不能切换焦点。
- 一上来就做完整自由像素漫游/碰撞体大地图。
- 无限随机地图。

**验收一句话：** 不看说明，你也能指出“我现在在工坊，市集在另一处，路还没通”。

#### B. 可生成行动

**定义：** 当前可做的事不是写死在关卡里的两个全局按钮，而是根据**当前焦点地点 + 世界状态 + 你的问题/意图**生成的 1–3 个行动候选。

**最小可见形态：**

- 焦点在织工/工坊时，可能出现“尝试更深分工”。
- 焦点在商人/市集时，可能出现“探路”或“开通交换”。
- 每个行动都显示：现在能不能做、不能做的原因、做了预期看到什么。
- Agent 可以用语音/文字建议“现在最值得试哪个”，但不能甩出内核没有的能力。

**明确不是：**

- 永远钉死的“开拓市集 / 织工赶单”两个罐头按钮。
- 你说任何话都立刻生效。
- Agent 现场发明新数值规则。

**验收一句话：** 你换焦点或世界状态变化后，行动列表会变；且每个行动失败/成功都有原因。

#### C. 一次连锁反馈

**定义：** 你只做一个行动，却能看见**至少两条以上、有因果顺序**的状态变化，而不是只闪一个数字或一句旁白。

**最小可见形态（例子）：**

1. 你执行“开通通往邻镇的交换”。
2. 先看到可触达订单增加。
3. 再看到工坊原料/纱线需求上升或库存去向变化。
4. 再看到织工态度从拒绝/等待变为可深化。
5. 现金或积压同步变化。
6. Agent 按这个顺序解释，并允许你点回对应事件和原文。

**明确不是：**

- 只有“现金 +2”这种单点反馈。
- 动画很忙，但状态没变。
- Agent 先编一段故事，事件后补。

**验收一句话：** 你能指着屏幕说“因为 A，所以 B，然后 C”，并且每一步都有事件可核对。

#### 附：一次同世界扩展

在上面三项之外，下一版还应证明：你追问后出现的是 **ExecutableWorldPatch**，不是新开一局。例如先只有村落与工坊，确认补丁后才出现通往邻镇的路。

## 11. 与 D007 / 原型的边界

| 项 | 决定 |
|---|---|
| T068 四站美术样张 | 机制不合格，不能代表 D007 通过 |
| 下一版 D007/空间原型必须证明 | 可走移动、无遮挡、到达地点、DOM 摘要；不是点击切地点 |

| 详述 | [`walkable-world-embedding.md`](./walkable-world-embedding.md) |

## 12. 实施切片（机制确认后，指哪打哪）

只在用户接受本文机制后进入实现。默认一次只打一个靶心：

1. **术语与类型合同**：把上表中文名固化到类型与 invitation 字段。
2. **地点拓扑呈现**：`PresentationPlan` 从线性 `entity_order` 改为地点节点 + 连接 + 当前焦点。
3. **可生成行动**：从 hardcode 两按钮改为当前 `ActionCandidate[]` 投影。
4. **一次连锁反馈**：单行动必须产出多事件时间线，并按因果播放/可读。
5. **同世界补丁**：`ExecutableWorldPatch` 确认 → 增量编译，不重置 world_id。
6. **语音等价入口**：final 语音与文字共用同一回合；停止/低置信零写入。

## 13. 验收标准（机制层）

用户或后续实现能明确回答：

1. 哪些是预制原语，哪些是本轮实时生成？
2. 实时语音在闭环里只做什么、不做什么？
3. 读者从提问到行动到回流原文，每一步谁可见、谁可写？
4. 地点拓扑、可生成行动、一次连锁反馈分别在屏幕上长什么样？
5. 第二轮追问如何改变**同一个**世界，而不是另开一局？
6. 失败、停止、拒绝补丁、来源过期时，世界为何不动？
